# СППР выбора поставщиков оборудования для диспетчерских комплексов

Сквозной учебный проект по дисциплине «Системы поддержки принятия решений».
Автор: Новосельцев Андрей Алексеевич, группа К4241.

**Предметная область.** Закупки комплектующих для типовых диспетчерских комплексов (стойки и пульты диспетчера) в крупном проекте; организация-пример - ООО «НИТА». ЛПР (лицо, принимающее решение) - директор организации.

**Категории оборудования и альтернативы:**

| Категория | Поставщики |
|---|---|
| ИБП (источник бесперебойного питания), стоечный 3 кВА | APC, Eltena, Vertiv, Piton |
| АВР (автоматический ввод резерва) | Elemy, Уралэнерготел, BONPET |
| КВМ-переключатели (клавиатура, видео, мышь) | Aten, Adder |
| Коммутаторы | HP (Aruba), Cisco, Eltex, MikroTik |
| Компьютеры и серверы | Lenovo, HP |

**Критерии:** k1 стоимость, k2 качество и технический уровень, k3 надёжность поставщика, k4 срок поставки, k5 гарантия и сервис в РФ, k6 санкционный риск канала, k7 российское происхождение.

## Данные

Все данные - из открытых источников:

- `data/raw/` - официальные курсы ЦБ РФ (USD, EUR, CNY, 2021-2026), ключевая ставка ЦБ РФ, индексы цен производителей Росстата;
- `data/research/` - сведения о поставщиках: статус на рынке РФ, каналы поставки, гарантия, публичные цены дистрибьюторов (с адресами страниц и датами обращения);
- `data/processed/alternatives.csv` - сопоставимые модели (по одной на поставщика в категории) с ценами, перепроверенными 13.10.2026; источники каждого значения - в `alternatives_sources.md`.

Показатели, по которым фактических данных нет (оценки 1-5 по k2, k3, k6, k7, часть сроков и гарантий), - экспертные оценки аналитика по явным правилам (`sppr/ratings.py`, `config/*.json`); они помечены как модельные. Поправки к сырым данным с обоснованием - в `config/data_adjustments.json`.

## Практики

| № | Практика | Результат |
|---|---|---|
| 1 | Постановка задачи | формальная постановка: ЛПР, цель, альтернативы, критерии, ограничения, источники данных; сбор открытых данных (`data/`) |
| 2 | Многокритериальный анализ | АНР-модель (метод анализа иерархий): матрица парных сравнений критериев, веса, ИС/ОС, итоговые приоритеты поставщиков; Excel-модель с живыми формулами (`outputs/p2/ahp_model.xlsx`) |
| 3 | Риски и неопределённость | дерево решений (networkx) для 4 стратегий закупки, сценарии курса по данным ЦБ, метод Монте-Карло, критерии Байеса, Вальда, Сэвиджа, Гурвица, CVaR95; оптимальная доля поставщика и пороги (scipy.optimize) |
| 4 | Оптимизационная модель | модель смешанного целочисленного линейного программирования (PuLP + CBC): сколько комплексов комплектовать у каждого поставщика - максимум полезности АНР при бюджете с учётом ожидаемых рисковых затрат, доле поставщика, сроках и санкционном риске; граница Парето, анализ чувствительности, проверка плана имитацией практики 3 (`outputs/p4/`) |
| 5 | База знаний | онтология OWL (`kb/sppr_suppliers.owl`, открывается в Protégé): 23 класса, 15 моделей, 15 вендоров, каналы поставки, требования комплекса; 15 продукционных правил (13 продублированы на SWRL), прямой логический вывод с объяснениями на Python; допуск передаётся в оптимизационную модель практики 4, 4 сценария требований (`outputs/p5/`) |
| 6 | Предиктивная аналитика и BI | прогноз курса USD/RUB на 13 недель (4 модели: случайное блуждание, дрейф, Хольт с затухающим трендом, градиентный бустинг; скользящая и отложенная проверка, интервалы по ошибкам проверки) и индексов цен производителей Росстата; прогноз стоимости плана практики 4; витрина SQLite и дашборд Apache Superset 6.1 в Docker (`bi/`, `outputs/p6/`) |
| 7 | Рекомендательный модуль | гибридные рекомендации ЛПР: отбор кандидатов базой знаний, ранжирование по полезности АНР с весами под контекст (типовой комплекс, осторожный ЛПР, импортозамещение), объём - оптимизацией практики 4, действия - правилами по сигналам рисков, базы знаний и прогноза; объяснения: вклады критериев, уверенность (устойчивость к разбросу весов), контрфакт по цене, сценарий что если (`outputs/p7/`, функция `recommend_for`) |

## Структура

```
config/      суждения ЛПР, оценки качества, поправки к данным, параметры моделей
data/        исходные (raw), собранные (research) и подготовленные (processed) данные
kb/          онтология предметной области с правилами SWRL (для Protégé)
bi/          стенд Apache Superset (Docker) и сборка дашборда ЛПР
sppr/        расчётные модули: ahp.py (АНР), ratings.py (оценки 1-5), risk.py (неопределённость), optimize.py (оптимизация), kb.py (база знаний), forecast.py (прогноз), recommend.py (рекомендации)
scripts/     запуск расчётов по практикам
outputs/     результаты по практикам (CSV, JSON, Excel, рисунки)
tests/       модульные тесты
tools/       сборка разделов паспорта СППР в Google Docs (Docs API)
```

## Запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/p2_ahp.py        # практика 2: АНР-модель -> outputs/p2/
python scripts/p2_excel.py      # практика 2: Excel-модель -> outputs/p2/ahp_model.xlsx
python scripts/p3_risk.py       # практика 3: дерево решений и анализ стратегий -> outputs/p3/
python scripts/p4_optimize.py   # практика 4: оптимальный план закупки -> outputs/p4/
python scripts/p5_kb.py         # практика 5: онтология, логический вывод, сценарии -> kb/, outputs/p5/
python scripts/p6_forecast.py    # практика 6: прогноз курса и цен, стоимость плана, витрина -> outputs/p6/
python scripts/p7_recommend.py   # практика 7: рекомендации и действия для ЛПР -> outputs/p7/
python -m pytest -q             # тесты
```

Дашборд ЛПР (Apache Superset 6.1, нужен Docker):

```bash
cp bi/.env.example bi/.env                     # задать SUPERSET_SECRET_KEY и пароль администратора
docker compose -f bi/docker-compose.yml up -d  # http://localhost:8088
python bi/build_dashboard.py                   # дашборд /superset/dashboard/sppr/ и экспорт bi/dashboard_export.zip
```

Онтологию можно открыть в Protégé: File → Open → `kb/sppr_suppliers.owl` (версия с выведенными фактами - `kb/sppr_suppliers_inferred.owl`); русские подписи - View → Render by label (rdfs:label). Правила SWRL выполняются во вкладке SWRLTab.

Сборка разделов отчёта (`tools/`) требует пакетов `google-api-python-client` и `google-auth`, ключа сервисного аккаунта в переменной `SPPR_GOOGLE_KEY` и ID документа в `SPPR_DOC_ID`; ключи в репозиторий не входят.
